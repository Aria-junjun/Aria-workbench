# 供应商全周期管理 PRD

## 1. 用户目标

用户能够回答：供应商供什么、实际表现如何、问题证据是什么、下一步应该做什么，以及是否适合承担更多产品或参与新品开发。

## 2. 页面结构

### 供应商总览

默认按以下优先级排序：质量异常、交付超时、供应关系缺失、改善逾期、数据不足、正常保持主供。正常供应商弱化显示，不生成待办。

字段：供应商、供货产品族、主供/备供、周期销售、实际入仓、退货率、绩效状态、证据、下一步动作。

### 供应商详情

固定区域：供应商概况、供应关系、经营表现、绩效明细、改善事项、能力档案、导出。

### 绩效明细

前端显示公式结果；点击“查看细则”或“导出明细”时，必须完整呈现原始值、基准值、计算公式、结果、证据来源、责任归属和数据缺失情况。

## 3. 标准值与判定规则

以下为 M2 的公司默认基准，订单或合作协议存在明确约定时优先使用约定值。所有标准值应可配置并保留生效日期。

### 交付

所需字段：需求日期、供应商承诺日期、实际入仓日期、约定数量、实际入仓数量。

```text
按时 = 实际入仓日期 ≤ 供应商承诺日期
按时足量 = 按时 且 实际入仓数量 ≥ 约定数量
延期天数 = 实际入仓日期 - 供应商承诺日期
```

状态：按时足量、按时不足、延期交付、部分延期、无法判断。没有承诺日期时不评价及时性。

### 沟通响应

默认工作时间基准：紧急事项 2 个工作小时，普通事项 1 个工作日，非紧急事项 2 个工作日。

```text
首次响应达标 = 首次有效回复时间 - 消息发出时间 ≤ 对应 SLA
问题闭环达标 = 问题解决时间 ≤ 约定解决日期 且 验收通过
```

“回复”必须是有效回复；自动回复、已读和无实质内容的回复不计入。

### 改善

状态：待制定、已制定、进行中、待提交验证、验证不通过、已完成、已逾期。

```text
按期完成 = 截止日期前提交 且 验证通过
改善完成率 = 已完成并验证通过的事项 ÷ 已到期事项总数
```

未到期事项不进入分母；没有截止日期的事项不能判定逾期。

### 质量

当前可用公式：

```text
退货率 = 实退数量 ÷ 实发数量 × 100%
```

退货率达到 5% 触发“质量复核”信号。该信号属于产品层质量信号，不自动认定供应商责任。

### 评分启用条件

```text
有基准值 + 有实际值 + 有明确责任归属 = 可评分
否则 = 未采集/无法判断
```

评分只汇总已经具备判定条件的指标；不能用满分替代缺失数据。

## 4. 导出要求

供应商导出至少包含：供应商信息、供应关系历史、产品族/SKU、周期、原始销售、原始入仓、退货数量、退货率、基准值、计算公式、绩效状态、证据来源、责任归属、改善记录和决策历史。

## 5. 非目标

M1 不建设完整库存系统、采购订单系统、财务对账系统或自动工艺能力判定；货盘报价只作为辅助证据保留。

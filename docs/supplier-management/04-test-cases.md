# 供应商绩效测试用例

| 编号 | 场景 | 预期结果 |
|---|---|---|
| TC-01 | 实际入仓日期早于承诺日期，数量足够 | 按时足量 |
| TC-02 | 日期按时但数量不足 | 按时不足 |
| TC-03 | 实际入仓晚于承诺日期 | 延期交付，并输出延期天数 |
| TC-04 | 没有承诺日期 | 交付状态为无法判断，不评分 |
| TC-05 | 紧急消息 2 个工作小时内有效回复 | 响应达标 |
| TC-06 | 普通消息超过 1 个工作日回复 | 响应超时 |
| TC-07 | 只有自动回复，没有有效回复 | 不计为响应达标 |
| TC-08 | 有问题但没有双方确认的解决日期 | 问题解决时效无法判断，不套用响应 SLA |
| TC-09 | 改善未到期 | 不进入完成率分母，不标记逾期 |
| TC-10 | 改善按期提交且验收通过 | 已完成，进入完成率分子和分母 |
| TC-11 | 改善提交但验证不通过 | 验证不通过，不计入完成率分子 |
| TC-12 | 本周期没有质量问题 | 质量问题闭环指标为 N/A，不记 0 分 |
| TC-13 | 实退数量 ÷ 实发数量达到 5% | 触发产品质量复核信号，不直接归责供应商 |
| TC-14 | 缺少实发数量 | 退货率无法判断，不补 0 |
| TC-15 | 只有部分维度有数据 | 总分按有效指标权重重新归一化 |
| TC-16 | 同一产品族已有主供关系 | 产品端默认继承，不重复生成确认任务 |
| TC-17 | 供应商后台更换主供 | 产品端显示关系变更并保留历史 |
| TC-18 | 同一事实重复导入 | 数据幂等，不重复累加 |
| TC-19 | 导出完整细则 | 包含原始值、基准值、公式、结果、证据和决策历史 |
| TC-20 | 云端同步暂时失败 | 本地数据保留，显示未同步，不丢数据 |

## 验收标准

- 任何“超时”都能定位到基准值和时间戳。
- 任何评分都能展开到原始数据和公式。
- 缺少基准时不会输出“正常”或“异常”的伪结论。
- 无异常时不会因为没有问题而得到 0 分或虚构满分。
- 导入同一文件两次不会造成数量翻倍。

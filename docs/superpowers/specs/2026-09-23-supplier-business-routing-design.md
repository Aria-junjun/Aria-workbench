# 供应商业务归位设计

## 目标

在不拆改现有采购和供应商页面的前提下，让同一供应商同时承载代发、入仓两类业务，并让多 Sheet 履约数据在正式写入前完成供应商、商品和业务模式归位。

## 核心规则

- 一家公司只保留一个供应商主档。
- 业务模式属于合作关系，不属于供应商身份；支持 `代发`、`入仓`、`代发+入仓`。
- 绩效按业务模式独立统计。代发使用周期履约指标，入仓使用采购单、交期、验收、品质和成本指标，不混算总分。
- 归位键为“供应商主档 + 商品/SKU + 业务模式 + 周期或采购单”。
- 原始 Excel 保持不变，所有 Sheet 均保留来源工作表和行号。

## 导入归位流程

导入采用五步确认：

1. 上传文件并识别商家、商品、售后 Sheet。
2. 展示读取统计：原始行数、有效记录数、自动匹配数、待匹配数、无法归属商品数。
3. 确认供应商别名。确认结果保存为可复用映射，后续周期自动匹配。
4. 确认商品归属供应商和业务模式。当前履约文件默认业务模式为代发，但允许调整。
5. 展示最终写入预览后正式导入。同一供应商、平台和周期重复导入时补齐或更新原记录，不重复创建。

未确认的供应商和商品不得写入正式档案，分别进入待建档和待归位区域。订单量不足的供应商仍保留周期证据，但不强制建立正式供应商档案。

## 数据结构

- 供应商别名映射：来源平台、来源名称、供应商 ID、确认时间。
- 商品归属映射：来源平台、商品名称、供应商 ID、业务模式、确认时间。
- 供应商合作模式由现有业务记录与商品关系派生，并允许人工修正。
- 代发周期记录继续使用 `dropship_period`；入仓记录沿用采购履约记录，二者在供应商详情中分区展示。

## 页面调整

- 批量导入弹窗增加读取统计、别名确认、商品归属和最终预览。
- 供应商详情增加“合作模式”，并分为“代发履约”和“入仓履约”。
- 管理总览只展示业务模式、风险、趋势、缺失数据和待办，不展示全部原始指标。
- 表格和边框沿用现有采购板块视觉，不新建独立设计体系。

## 异常与安全

- 同一来源名称映射到多个供应商时阻止导入并要求确认。
- 商品没有供应商归属时不得静默丢弃。
- 缺失指标显示“未采集”，不得按零计算风险或评分。
- 保存映射和正式导入作为一个操作完成；失败时不留下半完成数据。

## 验收标准

- 同一供应商可以同时显示代发和入仓关系，两套绩效互不混算。
- 当前工作簿三个 Sheet 的读取数量、匹配数量和未归位数量均可见。
- 名称不同的商家与售后记录经一次确认后可以合并，后续导入自动匹配。
- 无供应商列的商品记录必须经过人工归属，并可在供应商代发明细中查看。
- 重复导入同周期数据不会产生重复周期记录。

# 行业洞察外部 GPT 桥接设计说明

## 1. 目标

在不接入工作台内置 AI 的前提下，建立一条可复用的研究闭环：

> 研究对象与决策问题 → 固定字段任务包 → 外部 GPT 生成资料初稿 → 导入 AI 初稿 → 人工确认 → 六板块正式记录 → 行业洞察报告

本期目标不是自动完成行业判断，而是把产品经理的研究逻辑固化到字段、任务和审核状态中。

## 2. 范围

### 本期包含

- 保留现有六个行业洞察板块及顺序。
- 为六个板块补齐固定字段和字段说明。
- 根据研究对象与基础信息生成外部 GPT 任务包。
- 支持复制任务包到外部 GPT。
- 支持将外部 GPT 返回的 Markdown 初稿粘贴回工作台。
- 将导入内容保存为 AI 初稿，不直接覆盖正式记录。
- 支持逐字段确认、修改后采用、待验证和暂不采用。
- 正式报告只使用已确认内容，并保留来源和证据回溯关系。

### 本期不包含

- 工作台内置 AI 对话或模型 API。
- 自动全网持续抓取和定时监测。
- 自动判断行业阶段或产品机会。
- 自动把 AI 初稿写入需求探索、竞品分析、产品拆解或项目推进。
- 多模型选择、多人审核和权限系统。

## 3. 固定研究结构

### 3.1 字段协议原则

当前页面已经存在的字段是唯一可写入的正式字段协议。外部 GPT 不得自行新增“市场规模结论”“机会点”“成功标准”等无法在页面中归位的字段。

如果研究过程中出现页面没有单独字段的信息，必须按以下规则处理：

- 作为对应字段的补充说明写入，不另造字段；
- 作为来源、发布时间、可信度等证据元数据保存，不显示为新的研究字段；
- 如果无法归入任何现有字段，放入“待验证问题”或导入失败提示，不得静默丢失。

### 3.2 当前页面字段与外部 GPT 输出的唯一映射

| 页面板块 | 页面字段 | 外部 GPT 输出键 | 处理规则 |
| --- | --- | --- | --- |
| 研究目的 | 决策问题 | `purpose.decisionQuestion` | 只写本次需要支持的具体决策 |
| 研究目的 | 预期行动 | `purpose.expectedAction` | 写研究确认后准备采取的动作 |
| 行业边界 | 研究对象 | `boundary.object` | 写产品或行业对象的明确名称 |
| 行业边界 | 目标场景 | `boundary.scenarios` | 写实际使用场景，不扩展成泛人群描述 |
| 行业边界 | 地域 | `boundary.region` | 写地域口径 |
| 行业边界 | 时间范围 | `boundary.timeRange` | 写研究统计时间范围 |
| 行业边界 | 排除范围 | `boundary.exclusions` | 写明确不纳入的产品、用户或区域 |
| 四维分析 | 行业规模/发展趋势/市场占比/此消彼长 | `dimensions[].fact` | 只写观察到的事实或数据，不写结论 |
| 四维分析 | 行业规模/发展趋势/市场占比/此消彼长 | `dimensions[].judgment` | 写基于事实的判断，无法支撑时标记待验证 |
| 四维分析 | 行业规模/发展趋势/市场占比/此消彼长 | `dimensions[].evidence` | 写来源、口径或证据摘要；完整来源放证据元数据 |
| 四维分析 | 信息类型 | `dimensions[].tag` | 只能是事实、推断、待验证、策略建议之一 |
| 阶段判断 | 暂定阶段 | `stage.currentStage` | 只能使用页面已有阶段选项 |
| 阶段判断 | 阶段判断依据 | `stage.basis` | 合并规模、趋势、里程碑和行为变化证据 |
| 阶段判断 | 下一次转折因素 | `stage.nextInflection` | 写可能改变阶段判断的外部或内部因素 |
| 阶段判断 | 持续时间假设 | `stage.durationAssumption` | 写预计何时复盘或该判断有效的时间假设 |
| 产业链 | 层级 | `chainNodes[].layer` | 只能是上游、中游、下游、支持四类 |
| 产业链 | 角色 | `chainNodes[].role` | 写该节点在产业链中的角色 |
| 产业链 | 参与者与价值流 | `chainNodes[].participants` / `valueFlow` | 合并参与者、价值流和产品关联；当前页面没有独立产品关联字段 |
| 结论与下一步 | 机会判断 | `conclusion.opportunity` | 写值得验证的机会，不直接写已决定进入 |
| 结论与下一步 | 主要风险 | `conclusion.risks` | 写可能阻止判断成立的风险 |
| 结论与下一步 | 待验证问题 | `conclusion.unverifiedQuestions` | 承接无法确认或无法归类的关键问题 |
| 结论与下一步 | 下一步动作 | `conclusion.nextAction` | 写动作和目标模块，当前页面不拆分独立导入字段 |

`targetUsers`、`analysisTheme` 属于新建研究时的基础信息，不属于六步工作区的新字段。`nextModule`、`milestones`、`productRelation`、`evidenceIds` 是数据模型中的内部字段；在当前页面没有对应输入控件前，外部 GPT 不得把它们作为独立字段输出。

### 基础信息字段

新建研究页面的基础字段只有：

- 分析项目名称：`title`
- 产品/产品族：`productName`
- 目标用户：`targetUsers`
- 分析主题：`analysisTheme`
- 决策问题：`decisionQuestion`
- 预期行动：`expectedAction`

其中“目标用户”和“分析主题”是研究上下文，不在六步工作区重复创建字段。

### 六个板块的探究口径

- 研究目的只回答“决策问题”和“预期行动”，不要额外生成研究背景或成功标准。
- 行业边界只填写页面已有的研究对象、目标场景、地域、时间范围和排除范围。直接竞品、替代方案等内容如果需要出现，放入“排除范围”的边界说明或四维分析对应字段，不增加新字段。
- 四维分析的每个维度只能填写“观察事实、判断、证据、信息类型”。用户与场景、价格、销量、季节性、竞品变化等都必须归入四个维度之一，不能另起章节。
- 阶段判断只能填写“暂定阶段、阶段判断依据、下一次转折因素、持续时间假设”。规模、趋势、里程碑和行为变化统一写入“阶段判断依据”。
- 产业链每个节点只能填写“层级、角色、参与者与价值流”。材料、工艺、渠道、成本和风险都应作为参与者与价值流中的说明，不新增独立字段。
- 结论与下一步只能填写“机会判断、主要风险、待验证问题、下一步动作”。已确认事实和关键判断回到四维分析；模块建议写进下一步动作。

AI 只能基于证据生成候选内容，不能替用户确认阶段、机会或策略。

## 4. 外部 GPT 任务包

任务包由工作台根据基础信息和固定字段生成，必须包含：

- 研究对象和研究边界
- 六个板块及字段清单
- 每个字段的研究问题和填写口径
- 公开来源、发布时间和抓取时间要求
- 事实、推断、假设的区分要求
- 无数据时填写“未找到”，禁止编造
- 输出 Markdown 固定模板
- 每条关键结论必须附来源或标记待验证

任务包只复制研究上下文和字段要求，不包含不必要的内部经营数据。用户可在复制前编辑或脱敏。

## 5. 导入 AI 初稿

用户将外部 GPT 输出粘贴回工作台后，系统按固定标题和字段识别内容。导入结果保存为草稿对象，至少包含：

- sectionKey
- fieldKey
- aiDraft
- evidence
- sourceUrl
- sourceName
- publishedAt
- capturedAt
- confidence
- needsVerification
- reviewStatus

`reviewStatus` 取值：`draft`、`accepted`、`edited`、`needs_verification`、`rejected`。

解析失败时不得静默写入正式字段，应显示未识别内容，并允许用户手动放入指定字段。

## 6. 人工确认与正式记录

每个字段展示三个层次：

1. 原始证据
2. AI 初步判断
3. 我的最终判断

只有用户点击确认后，内容才进入正式记录。正式记录需要保留：

- 最终内容
- 原始 AI 草稿
- 修改后的内容
- 修改时间
- 来源和证据
- 确认状态

报告只读取确认状态为 `accepted` 或 `edited` 的字段；`draft` 和 `needs_verification` 只能作为信息缺口提示，不得伪装成正式结论。

## 7. 联动边界

本期只提供“建议导入位置”和引用预览，不自动写入后续模块。

- 用户问题、场景、待验证假设 → 需求探索
- 竞品、替代方案、差异点 → 竞品分析
- 功能、材料、体验和技术因素 → 产品拆解
- 已确认行动和验证任务 → 项目推进

后续模块导入时必须保留行业洞察项目、板块、字段和来源引用。

## 8. 页面组成

- 行业洞察首页：项目、完成进度、证据数量、待确认数量、报告入口
- 研究基础信息区：固定上下文和决策问题
- 六步工作区：固定字段和板块导航
- 资料/证据抽屉：字段相关证据、来源和时间
- 外部 GPT 任务包面板：生成、编辑、复制
- AI 初稿导入面板：粘贴、解析、识别失败提示
- 字段审核区：采用、修改后采用、待验证、暂不采用
- 报告预览：只显示确认内容，标记信息缺口和引用

## 9. 真实性与时效边界

只接受用户主动提供或外部 GPT 返回的公开资料。每条证据记录来源、发布时间和导入时间。

- 搜索热度只能作为需求信号，不能直接等同市场规模。
- 单个平台商品销量不能直接等同市场占比。
- 单条用户评价不能直接代表整体用户需求。
- AI 推断必须标记为推断或待验证。
- 超过研究时间范围或缺少来源的内容不能自动进入正式结论。

## 10. 验收标准

- 用户可以创建包含固定基础字段的行业洞察项目。
- 用户可以看到六个板块的固定字段和填写口径。
- 用户可以生成包含六板块字段的外部 GPT 任务包并复制。
- 用户可以粘贴 Markdown 结果并导入 AI 初稿。
- 导入内容不会直接覆盖正式记录。
- 用户可以逐字段审核并修改。
- 报告只展示已确认内容，并显示未确认字段和来源。
- 刷新和重新打开项目后，基础信息、AI 草稿、审核状态和正式记录都能保留。

# 供应关系维护与决策历史设计

## 1. 目标

把“货盘匹配、入仓证据、实际主供/备供”区分开，并形成可执行的供应关系闭环。

本阶段只处理已经入仓的产品，不新增供应商评分体系，不替代聚水潭的采购、库存和订单功能。

## 2. 业务规则

### 2.1 产品族默认关系

- 用户在产品族层选择主供供应商后，默认覆盖该产品族下全部有效 SKU。
- 可选设置一名或多名备供供应商，但备供不等于当前采购来源。
- 产品族关系只代表当前经营决策，不代表每个 SKU 都已经完成货盘规格匹配。

### 2.2 SKU 例外关系

- 某个 SKU 与产品族默认供应商不同，或暂时没有供应商时，可建立 SKU 级例外。
- SKU 例外优先于产品族默认关系。
- 取消 SKU 例外后，恢复继承产品族默认关系，不删除历史记录。

### 2.3 证据与状态

关系状态必须带依据，不允许只保存一个无来源的“已确认”标签：

- `货盘已匹配`：规格或编码已与货盘建立匹配关系。
- `有入仓证据`：本月或历史入仓数据证明该供应商实际供过货，但尚未建立正式主供关系。
- `实际供应已确认`：用户明确将该供应商设为主供或备供。
- `待确认`：已有候选或证据，但供应关系尚未确认。

货盘匹配不自动升级为主供关系；入仓证据也不自动替换当前主供。

## 3. 操作入口

### 3.1 供应商详情页

在“供应商决策闭环”区域增加：

- 设为主供
- 设为备供
- 调整供应关系
- 查看影响的产品族和 SKU

操作时填写：

- 关系范围：产品族默认 / 单个 SKU
- 生效月份
- 变更原因
- 依据：货盘报价、实际入仓、用户确认或其他记录

### 3.2 产品主表

产品族行显示：

- 当前主供
- 备供数量
- SKU 例外数量
- 待确认数量

展开 SKU 后显示：

- 继承产品族关系，或 SKU 例外
- 当前供应商
- 关系依据
- 生效月份

点击待确认数量，跳转到待处理列表，而不是跳转到无关的供应商详情页。

### 3.3 货盘报价页

保留规格匹配和报价比较功能，但明确显示：

- 货盘匹配状态
- 是否已被当前主供/备供关系采用
- 是否只有入仓证据

不在货盘页直接自动修改主供关系。

## 4. 数据关系

```text
产品族
  ├─ 有效 SKU
  ├─ 产品族默认主供/备供关系
  └─ SKU 级例外关系

SKU
  ├─ 货盘规格匹配
  ├─ 月度实际入仓证据
  └─ 当前生效供应关系

供应关系变更
  ├─ 生效月份
  ├─ 变更原因
  ├─ 证据来源
  └─ 不可变决策历史
```

计算优先级：

1. SKU 级例外关系
2. 产品族默认关系
3. 实际入仓证据
4. 货盘匹配候选
5. 待确认

## 5. 联动结果

### 产品管理

产品主表可以回答：当前产品由谁供应、哪些 SKU 有例外、哪些关系仍未确认，以及供应关系是否影响继续经营判断。

### 供应商管理

供应商详情可以回答：当前负责哪些产品族和 SKU、是主供还是备供、关系何时生效、为什么被保留或替换。

### 供应决策

供应商决策页只使用已经确认的关系做行动建议；货盘匹配和入仓证据作为依据，不直接当作结论。

## 6. 非目标范围

本阶段明确不做：

- 自动供应商评分
- 自动替换主供供应商
- 聚水潭采购、库存、订单功能复制
- 每日库存追踪
- 财务口径的利润核算

## 7. 验收标准

- 产品族设置主供后，所有有效 SKU 默认显示该供应商。
- 单个 SKU 设置例外后，仅该 SKU 显示例外供应商，其余 SKU 不变。
- 取消例外后恢复继承产品族关系。
- 每次变更都保留生效月份、原因和依据。
- 刷新页面后关系仍存在，且产品主表、供应商详情页、供应决策页显示一致。
- 货盘匹配不会自动改变主供关系。
- 无供应关系的数据会进入可跳转的待确认列表。

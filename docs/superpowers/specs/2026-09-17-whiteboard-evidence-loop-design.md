# 静电白板贴留痕问题：证据闭环试点设计

## 1. 目的与范围

本试点以“静电白板贴留痕问题”为唯一真实产品对象，验证工作台能否把多模块研究组织成一条可追溯、可复核、可继续行动的证据链。

目标链路：

> 行业洞察 → 需求探索 → 竞品分析 → 产品拆解 → 机会产品验证中心 → 正式研究报告

本试点不包含：

- 自动联网抓取并直接写入正式记录；
- 自动做商业化、采购、入仓或生命周期决策；
- 重构完整产品生命周期模型；
- 用 AI 结论覆盖用户原始资料或已经确认的内容。

## 2. 核心原则

1. **原始资料优先**：用户输入、外部 AI 初稿、人工修改稿、最终确认稿分别保存，不互相覆盖。
2. **AI 只做辅助**：AI 可以整理、分类、提取字段、指出缺口和冲突，但不能替用户确认事实或做经营决策。
3. **引用可追溯**：引用必须记录来源模块、来源项目、来源字段、引用时间和内容快照。
4. **引用不等于继承**：被引用内容进入目标模块后是参考副本，源内容变化不会静默改写目标内容。
5. **事实与判断分离**：内容必须区分事实、推断、待验证；没有证据时明确标记“未找到”或“待验证”。
6. **冲突显式保留**：不同模块或不同 AI 草稿产生冲突时并列展示，保留各自来源和状态，不自动选择“正确答案”。

## 3. 模块职责与固定输出

| 模块 | 固定回答的问题 | 输出性质 |
| --- | --- | --- |
| 行业洞察 | 行业边界、规模、趋势、产业链是什么 | 行业事实、判断依据、证据缺口 |
| 需求探索 | 需求是否真实、样本是否有限、属于哪类需求 | 用户证据、KANO 参考、样本限制、验证动作 |
| 竞品分析 | 竞品范围、差异和证据是什么 | 对比事实、差异判断、证据缺口 |
| 产品拆解 | 原因、方案、优先级和验证动作是什么 | 原因假设、方案假设、优先级依据、行动 |
| 机会产品验证中心 | 当前证据是否足以支持继续验证 | 证据摘要、冲突、缺口、阶段状态 |
| 正式研究报告 | 当前知道什么、还不知道什么、下一步做什么 | 中立结论与可执行验证计划 |

机会产品验证中心不把研究对象自动认定为商品，也不替代后续商品经营管理。

## 4. 数据与引用设计

### 4.1 内容来源类型

每条内容至少具备以下状态之一：

- `original`：用户原始输入或用户提供的资料；
- `ai-draft`：外部 AI 生成但尚未确认的初稿；
- `edited`：用户修改后的内容；
- `confirmed`：用户确认后进入正式模块的内容；
- `inference`：基于证据的推断；
- `to-verify`：需要进一步验证的内容。

### 4.2 引用快照

引用记录至少包含：

- 来源模块；
- 来源项目；
- 来源字段；
- 来源内容快照；
- 引用时状态；
- 引用时间。

目标模块可以编辑引用副本，但必须保留“引用自”标识。目标编辑不会反向修改来源。

### 4.3 当前试点允许的引用方向

推荐按研究逻辑单向流动：

`行业洞察 → 需求探索 / 竞品分析 → 产品拆解 → 机会产品验证中心 → 正式研究报告`

允许目标模块引用上游资料；暂不允许循环引用和跨模块自动回写。需要反向参考时，通过人工选择已有项目或复制引用记录完成。

## 5. AI 任务与审核流程

三个研究页面统一采用以下流程：

1. 页面根据固定字段生成外部 GPT 任务包；
2. 用户复制任务包，在外部 GPT 中生成 Markdown 初稿；
3. 用户粘贴回页面；
4. 系统按固定字段识别，并用中文显示所属板块和字段；
5. 未识别内容保留在原文区，不丢弃；
6. 用户可以逐字段修改；
7. 用户选择“确认保存 AI 初稿”或保存修改稿；
8. 页面保存 AI 初稿、修改记录和最终确认内容；
9. 已确认内容才能被其他模块引用。

未确认的 AI 初稿只能作为当前项目草稿，不得进入机会产品验证结论。

## 6. 冲突处理

冲突分三类：

1. **数值冲突**：规模、销量、比例、时间等不一致；
2. **事实冲突**：不同来源对同一事实描述不同；
3. **判断冲突**：不同模块对趋势、需求强度或方案价值判断不同。

系统只负责提示冲突并展示来源。用户需要选择：

- 保留双方并标记待验证；
- 指定一条为当前采用内容并记录理由；
- 标记其中一条为不采用并保留历史。

没有来源、时间或口径的内容不得因为 AI 语气更确定就被优先采用。

## 7. 试点验收标准

试点完成的最低条件：

- 恢复文档不会导致原始内容消失；
- AI 识别失败时原文仍然可见、可复制、可重新识别；
- 三个研究页面都有一致的“导入、识别、修改、确认、历史”流程；
- 确认后的字段可以被下游项目引用；
- 引用页面能显示来源模块、项目、字段和快照时间；
- 来源内容更新后，目标引用不会被静默覆盖；
- 冲突内容并列保留并可以转为待验证动作；
- 正式报告能区分事实、推断、待验证和未决策事项。

## 8. 停止和扩展条件

只有当试点至少满足以下五项中的四项，才进入更大范围建设：

1. 重复填写明显减少；
2. 结论可以追溯到具体来源字段；
3. 信息缺口能转为下一步行动；
4. 冲突没有被自动掩盖；
5. 正式报告可被用户复核并用于下一步研究。

若数据恢复、引用追溯或冲突处理任一项失败，暂停扩展，先修复基础能力。

## 9. 后续阶段

试点通过后再依次考虑：

1. 将机会产品验证中心正式化；
2. 增加产品进程与研究项目的关联；
3. 明确进入入仓产品的证据门槛；
4. 单独设计产品生命周期管理；
5. 再评估是否引入联网检索或页面内 AI。

在此之前，不把“研究链路已打通”表述为“产品全生命周期已完成”。

# 供应商全盘总览与业务追溯工作区

## 已确认目标

用户于 2026-09-21 确认采用：管理总览看全盘，供应商详情查看完整业务记录，每项结果可追到原始依据；不重复录入基础资料，不将未知值视作零，不根据附件上传动作自动判定合格。

## 现状核查

- 已有供应商、货盘报价、SKU、月度入仓汇总、供应关系、能力与绩效记录，必须保留。
- 生命周期 MVP 使用通用文本字段；保留历史原文，不推测其含义并强行转换为结构化事实。
- 月度入仓汇总有来源文件名、工作表、导入时间，但不等于逐笔采购订单，也不代表原文件已经保存。
- 目前发现的文件上传接口仅用于头像，不可复用于供应商敏感业务附件。

## 导航与展示

左侧保留管理总览、寻源与比价、供应商档案、货盘报价。原准入、合作、绩效、退出路由继续兼容，历史记录不删除；供应商详情汇总相应记录。

供应商详情以只读列表和详情为默认视图；新增、编辑进入独立表单视图，取消修改不影响已保存数据。页签：综合概况、基础与资质、产品与报价、寄样与核样、合作约定、采购与履约、改善与退出。

列表展示对象、产品范围、状态、关键日期、待办、附件数量；空内容显示简短的尚无记录提示，不铺开空表格。状态不是填表百分比。

## 数据边界与复用

供应商基础资料一处维护；报价复用现有货盘报价。寻源是多供应商比较入口，不独属于一家供应商。从供应商发起动作自动带入其 ID，从寄样开始核样自动带入样品与规格版本。

新增业务记录通过稳定 ID 关联供应商、产品/SKU、报价、寄样、核样、合作与采购。拒绝跨供应商错误关联。关联不到的导入记录进入待匹配，不靠名称模糊猜测；旧数据原样保留。

合作范围精确到产品、规格版本、交付方式，某个样品通过不意味着全供应商、全部 SKU 准入。重复寄样、复测、重新报价保留历史，采购引用当时的条款版本，不随最新报价改变。

## 执行信息

### 基础与资质

复用名称、联系人、联系方式、店铺链接、来源平台、供货方式。补充合同主体、生产方式及实际生产方、收款与开票主体关系；主体差异需说明与依据。按产品和销售场景记录适用资质、覆盖范围、有效期和核验状态。不为所有产品强制套用同一认证清单，不自动解释报价中的“税点”为法定税率。

### 产品与报价

产品/SKU、规格版本、产品链接、报价日期及有效期、计价单位、价格、含税及运费口径、起订量、交期；附件保留原报价及书面回复。只有同规格、单位、数量条件、税运口径可比时才计算差额，不默认最低价最优。

### 寄样

对应供应商与产品、样品名称/编号、规格版本、数量和单位、寄出日期、物流单号、收到日期；按实际动作填写，未寄出无需填物流。照片与寄样单挂在本条记录。状态：待寄出、运输中、已收到、已取消。

### 核样

关联一次寄样；逐项记录检验项目、方法、预先设定的合格标准、实测值/现象、判定、证据。记录检验日期和核验人。数字项目与外观等描述项目分别支持，不强制把所有结果数字化。无标准或未完成检验不能自动通过；复测形成关联记录。允许试单是人工决定，与核样完成状态分开。

### 合作约定

适用 SKU/规格、报价版本、正常/紧急交期、售后责任、结算口径、双方确认日期及凭据。按入仓、代发、定制显示条件：代发增加截单、库存通知、退货规则；定制增加封样版本、改样/模具约定、试产边界。历史阶段原文可查看，不重复抄写。

### 采购与履约

逐笔记录订单号、日期、供应商、SKU、数量、单位、金额及口径、约定日期、实际收货/发货、异常，关联适用报价与合作版本。允许先保存不完整草稿；显示数据来源是导入还是人工录入。现有月度入仓数据独立展示为汇总依据，不伪造订单号或拆分成虚构订单。

导入前预览、明确列映射与待匹配项、重复检测。首期支持通用 CSV/XLSX，不宣称已接入平台或 ERP。附件下载、导入和业务事实核验是不同动作。

## 管理总览口径

采购分布按供应商、产品、供应商×产品展示，显示时间、金额口径、数据覆盖、未归属金额，可下钻明细。订单与月度汇总不得叠加造成重复计数，分别选择数据来源。

风险关注：未验证备供、实际交期异常、未解决质量问题。工作关注：待寄样、待核样、待确认合作与逾期任务。经营效果仅显示可比、可追溯数据支持的变化；报价降幅不等于已实现节省。

## 附件方案与待确认选择

方案 A：本机私有目录保存原件（建议首期）。不放 public，不将文件正文塞入浏览器业务 JSON。通过登录校验的接口读取与下载；生成随机标识、防路径穿越、类型及大小限制、上传失败明确提示、禁止覆盖旧版本；保存原始文件名、大小、上传时间、校验摘要。完整备份必须包含附件及清单，普通业务 JSON 备份明确不包含文件。其他电脑只有同步记录时，提示附件在原工作台主机，不显示虚假可用状态。

方案 B：有访问控制的云附件存储。需确认现有云端的桶、权限和容量配置；不得创建公开业务文件链接，也不未经批准引入新的外部文件服务。适合跨设备查原件。

上传证明只代表收到文件，不代表证据已核验。替换文件新增版本，不删除旧证据；本期不提供永久销毁附件动作。

两者会改变备份、访问和跨设备使用方式；编码附件持久化之前由用户确认 A 或 B。

## 分批交付与验收

1. 先完成供应商只读工作区、独立寄样核样记录及关联报价、附件基础；确认新增/编辑/取消/重新打开完整闭环。
2. 完成合作与采购记录和通用导入；证明从采购能逐级追溯到适用报价、核样和寄样，历史版本不变。
3. 总览引用上述真实记录；核查筛选、下钻、金额占比、未知与重复统计边界。

测试至少覆盖：空数据、缺依据、跨供应商错误关联、同 SKU 多次寄样复测、草稿保存、旧数据兼容、版本冲突、上传失败/无权限/越界路径、备份恢复后附件可读、订单与月汇总不重复计算。浏览器验证只读默认、新增编辑入口和追溯链，不向真实业务数据注入演示记录。

## 不做的事情

不重建 ERP，不自动付款/发订单，不自动判定法律合规，不引入无依据综合评分，不为了展示完整而填充虚构记录。不修改与本次供应商工作区无关的产品研究功能。

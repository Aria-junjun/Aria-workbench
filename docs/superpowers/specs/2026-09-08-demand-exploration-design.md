# 需求探索板块设计规格

## 1. 目标

在现有工作台中新增一个按功能划分的“需求探索”板块，帮助企业产品相关人员按照课程节奏学习并执行 KANO 需求分析。

第一版的目标不是自动替执行人提出问题，而是让执行人完成思考、填写和判断；系统负责解释模型、校验输入、执行分类和公开计算过程，最后形成可复核的需求分析记录。

## 2. 范围

### 本期实现

1. 提出需求
2. 设计 KANO 正向/反向问题
3. KANO 对照矩阵
4. 多人回答录入与统计
5. BI/SI（Better/Worse）计算
6. 多需求四象限比较
7. 需求分析结果与过程记录

### 本期不实现

- HMW 五步法，仅预留入口
- 竞品拆解，仅预留入口
- 产品经营、供应商绩效、ERP 数据接入
- 自动生成完整问题文本
- 自动替用户做最终产品决策

## 3. 信息架构

新增一级板块：`需求探索`。

板块内部使用独立功能页面，页面之间可以通过同一个分析记录关联，但不强制串行：

- 提出需求
- KANO 问题设计
- KANO 对照表
- 多人统计
- BI/SI 计算
- 需求四象限
- 分析结果

每个分析记录可选关联产品、产品族、用户群体和使用场景。未关联业务对象时，也可以作为独立学习练习使用。

## 4. 核心流程

### 4.1 提出需求

执行人填写：

- 用户
- 场景
- 当前问题
- 要解决的目标
- 目标产品或产品族（可选）

系统提示执行人先写问题，不直接写解决方案。

### 4.2 KANO 问题设计

执行人填写一个可被用户感知的产品特性，并自行设计两道问题：

- 提供该特性时，用户的感受
- 不提供该特性时，用户的感受

系统只做结构性校验：

- 两道问题是否围绕同一特性；
- 是否一正一反；
- 是否混入多个特性；
- 是否包含明显诱导表达；
- 是否适合目标用户理解。

用户可以跳过学习说明，但任何页面都保留“查看模型说明”入口。

### 4.3 KANO 对照矩阵

界面呈现课件中的二维回答矩阵：

- 行：反向问题的五种回答；
- 列：正向问题的五种回答；
- 单元格：A/O/M/I/R/Q 分类。

矩阵提供“学习模式”和“查看模式”：

- 学习模式：点击单元格，显示该组合为什么属于对应分类；
- 查看模式：查看本次回答已经落入的分类和数量。

### 4.4 多人统计

支持手动录入和表格导入两种方式。每条回答保留：

- 回答人/角色（可选）
- 正向回答
- 反向回答
- 回答时间
- 数据来源或备注（可选）

系统根据矩阵映射统计 A/O/M/I/R/Q 数量和占比。R、Q 单独呈现，不隐藏异常回答。

### 4.5 BI/SI 计算

系统公开呈现公式、代入值和结果：

```text
SI / Better = (A + O) / (A + O + M + I)
DSI / Worse = -(M + O) / (A + O + M + I)
```

界面必须同时显示：

- A/O/M/I/R/Q 的原始数量；
- 有效样本分母；
- 公式代入过程；
- SI 与 DSI 数值；
- 样本量不足或 R/Q 占比较高的提示。

R、Q 不进入 SI/DSI 分母，但必须进入结果解释和数据质量提示。

### 4.6 四象限比较

当一个项目包含两个及以上需求时，可以将需求放入四象限：

- 横轴：SI/Better；
- 纵轴：DSI/Worse；
- 中心线：当前需求集合的平均值；
- 每个点：一个需求，可点击查看原始计算依据。

四象限只提供比较，不自动生成产品决策。

## 5. 结果输出

结果页必须同时展示三层信息：

1. 模型结果：例如“更接近期望属性 O”；
2. 计算依据：分类数量、样本量、公式代入和四象限位置；
3. 可信度限制：样本不足、角色偏差、R/Q 比例高、问题设计可能有歧义等。

结果可保存为分析记录，并可选关联产品或产品族。结果不覆盖产品主表，也不直接改变产品状态。

## 6. 数据结构边界

新增数据应独立于供应商绩效和产品经营数据，至少包含：

- `analysisId`
- `title`
- `productId` / `productFamily`（可选）
- `userType`
- `scenario`
- `problem`
- `goal`
- `feature`
- `functionalQuestion`
- `dysfunctionalQuestion`
- `responses`
- `counts`
- `si`
- `dsi`
- `quadrantPosition`（可计算）
- `status`
- `createdAt` / `updatedAt`

回答矩阵映射应作为独立纯函数实现，避免把分类规则写死在页面组件内。

## 7. 错误处理与边界

- 未填写正向或反向问题时，允许保存草稿，但不能生成正式结果；
- 正反问题为空或明显相同，提示补充；
- 样本量为 0 时不计算 SI/DSI，显示“待收集回答”；
- 有效样本分母为 0 时显示 `N/A`，不能显示 0 分；
- 导入表格存在无效回答时，保留原始行并标记 Q/待修正；
- 结果生成失败时不丢失草稿；
- 删除分析记录前需要二次确认，并保留可恢复的历史记录策略。

## 8. 验证标准

### 功能验证

- 可独立创建分析记录；
- 可跳过学习说明；
- 可单独进入任一已保存环节；
- 矩阵分类与课件规则一致；
- SI/DSI 公式代入过程正确；
- R/Q 不进入分母但会在结果中提示；
- 多个需求可显示四象限；
- 空数据和错误输入不会生成虚假结论。

### 交互验证

- 用户能看出当前正在学习/操作哪个环节；
- 系统不会直接替用户生成完整问题；
- 公式和分类过程可追溯；
- 各模块视觉上独立，不把 HMW、竞品或产品经营混入本期界面。

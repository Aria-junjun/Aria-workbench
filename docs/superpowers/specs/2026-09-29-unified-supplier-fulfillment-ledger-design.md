# 供应商统一履约工作区设计

## 目标

将采购入仓履约与代发周期履约收敛到同一履约工作区，避免业务台账将多张明细表全部展开导致页面过长；同时保留两类业务各自的数据源、统计周期、指标和决策口径。

## 页面结构

供应商业务台账中，寄样、核样、合作约定等既有业务入口维持不变；采购履约与代发周期履约由同一履约入口承载。履约工作区有两个业务类型选项：「入仓」和「代发」，以及三个互斥视图：

1. **履约总览**：默认视图，只展示当前业务类型的关键汇总、数据覆盖和风险摘要，不默认展开原始数据行。
2. **导入明细**：按导入批次列出来源、周期、记录数和业务类型；可展开批次核对原始行。
3. **履约对比**：按供应商比较并支持关键指标排序；入仓和代发使用不同列与周期选择，禁止跨业务混算。

## 数据与口径

- 入仓来源为 `monthlyInboundSnapshots`，展示月度实际入仓数量和已知结算金额；缺失值显示「未采集」，结算金额不表述为付款额。
- 代发来源为现有供应商周期履约及商品周期数据；订单、GMV、揽收、退款/售后等沿用既有计算规则和风险规则。
- 供应商档案、业务来源记录和商品/供应商映射继续分离保存；删除履约导入批次不会删除供应商档案或映射关系。
- 导入明细是源数据核查入口；总览与对比只读取、聚合源数据，不复制成另一套事实记录。

## 删除安全与影响

- 批次删除必须经过影响预览，不提供列表行的一键删除。
- 预览展示批次标识、来源文件/工作表、期间、将删除的源记录数及受影响页面/数据视图。
- 用户必须先下载完整数据备份，再逐项确认风险提示并输入该批次标识；所有门槛通过后删除按钮才可用。
- 删除入仓源快照会使对应记录从供应商业务台账、入仓产品主表及管理总览消失；删除代发源数据会使相关代发明细和派生总览/比较结果同步更新。
- 新入仓导入写入稳定的导入批次标识。历史记录缺少该标识时，按来源文件、工作表、月份和导入时间归组，并在确认页列出精确匹配记录。
- 导入过程曾按 SKU/产品与月份更新既有快照；已被后续导入覆盖的旧值不再存在于当前记录中。删除前备份用于恢复当前数据，不承诺恢复已被覆盖的历史版本。

## 验收条件

- 页面一次只呈现一个履约视图，不再把总览、全部入仓明细、代发明细、待建档队列和比较表连续铺成长页面。
- 入仓和代发选择可切换；各自显示不同的周期控件、指标、空值语义与排序列。
- 批次删除显示明确的跨页面影响、备份入口、多项确认及批次标识复核；取消或确认条件不足均不会删除数据。
- 删除仅作用于预览列出的源记录；供应商主档和商品/供应商映射保持不变。
- 当前既有的业务记录、档案跳转、代发批次安全删除和周期聚合行为继续通过回归测试。

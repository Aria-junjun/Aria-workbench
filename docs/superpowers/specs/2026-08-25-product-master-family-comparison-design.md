# 入仓产品主表：产品族经营数据展开与 SKU 对比

## 背景

当前入仓产品主表把产品族、多个 SKU 编码、供应方案和经营数据压在同一行，导致主表过宽，无法快速比较不同产品族在整体盘子中的经营权重。此次调整只改变呈现层，不删除既有 SKU、月度快照、入仓数据或供应商关联。

## 目标

1. 主表以产品族为决策单位，保持纵向比较不同产品族。
2. 经营数据不删除，改为产品族行展开后的横向指标区。
3. 产品名称左侧的展开按钮专门用于查看该产品族的 SKU 对比。
4. 主表不再堆叠完整内部 SKU 编码；SKU 编码只在展开区展示。
5. 让关注提示能够说明判断依据，而不是只显示一个状态文字。

## 页面结构

### 产品族主表

主表保留以下列：

- 产品族：产品族名称与展开/收起按钮；下方保留品类和 SKU 数。
- SKU 数：该产品族包含的 SKU 数量。
- 品类编码：预留一个可选的产品族编码；当前没有可靠编码时显示“未填写”，不影响统计。
- 供应方案：主供、备供、待处理数量和实际供货供应商。
- 经营状态：继续经营、需要优化、淘汰或观察。
- 关注提示：用短文本说明需要关注的原因，来源于已有月度经营数据和供应决策结果。

主表不再直接展示完整 SKU 编码列表，也不删除这些编码；它们只在展开区显示。

### 同表展开：产品族与 SKU 共用列

点击产品名称左侧的“＋”后，不另起一块卡片或独立表格，而是在同一张主表中插入该产品族的 SKU 明细行。产品族汇总行和 SKU 明细行共用同一组列，保证上下直接对齐，便于横向比较不同产品族、纵向比较同一产品族的 SKU。

主表和展开行只保留最有决策价值的原始数据：

- 产品/SKU：产品族名称；展开后显示内部 SKU 编码和规格。
- SKU 数：产品族汇总行显示数量；SKU 行不重复显示。
- 本月实发：产品族汇总为全族合计，SKU 行为单 SKU 数值。
- 较上月：显示实发数量变化，帮助识别增长或下滑。
- 实际入仓：产品族汇总与 SKU 行分别显示当前统计月入仓数量。
- 退货率：产品族汇总按实退/实发汇总计算；SKU 行显示单 SKU 值。
- ERP 成本基准：用于供应商成本判断的参考，不做财务利润核算。
- 关注提示：显示产品族或 SKU 的主要异常与下一步判断依据。

实际库存、可售库存合并为一个“库存 / 可售”列；当前没有可靠数据时显示“待采集 / 待采集”，待后续有稳定库存来源时直接填入，不再增加额外列。

SKU 行是产品族经营判断的证据，不改变产品族作为主决策单位的定位。

## 关注提示规则

关注提示优先使用已有数据生成，不制造新数据：

- 本月实发下降：提示“实发较上月下降”。
- 退货率存在且较高或上升：提示“退货率需复核”。
- 本月有入仓但经营数据缺失：提示“经营数据待补”。
- 供应方案存在待处理 SKU：提示“供应覆盖待补”。
- 没有触发上述规则：提示“当前无明显异常”。

若同时命中多个规则，最多展示最重要的两条，避免主表再次变长；完整依据在展开区查看。

## 数据与兼容性

- 不修改现有产品族归类、SKU 主表、月度经营快照和实际入仓快照的数据结构。
- 不删除旧的内部编码、报价、供应商关联或历史月份数据。
- 品类编码先作为可选展示/编辑字段预留；如果当前模型没有可靠存储位置，第一版可显示“未填写”，不阻塞经营数据展示。
- 实际库存和可售库存继续使用真实数据；没有输入时显示“待采集”，不以入仓数量代替库存。

## 验收标准

1. 主表宽度明显收窄，不再显示一串 SKU 编码。
2. 每个产品族仍能纵向比较 SKU 数、供应方案、经营状态和关注提示。
3. 展开产品族后，SKU 行直接插入同一张表，并与主表列完全对齐。
4. 同一列可以直接比较不同产品族的汇总值和同一产品族的 SKU 值。
5. 展开区域能看到该产品族的全部 SKU 与规格，不发生数据丢失。
6. 刷新页面后，已有月份数据、入仓数据和供应商关联保持不变。
7. 现有导入、保存月度快照和产品详情跳转继续可用。

# 组合决策工作区设计

## 目标

解决当前商业知识流程中的两个断点：进入单个工具后无法返回原推荐结果；一个复杂问题只能使用一个决策工具。

本轮目标是让用户可以从推荐结果中选择 1 至 3 个工具，在同一个工作区完成诊断、选择行动并保存一条组合应用记录。

## 范围

### 包含

- 推荐结果默认选择相关度最高的 2 个工具；只有 1 个结果时选择 1 个。
- 用户可以取消或增加选择，最多选择 3 个工具。
- 单个工具详情页提供“返回推荐结果”，并保留原问题。
- 新增组合决策工作区，按工具分组展示匹配原因、诊断问题、行动建议和不适用情况。
- 用户填写一份综合判断，并从所有工具的行动建议中选择最终行动。
- 保存为一条应用记录，`toolIds` 关联全部所选工具。
- 生成待办时保留行动对应的工具名称，避免来源不明。

### 不包含

- 不调用 GPT 自动生成综合结论。
- 不自动解决不同工具之间的策略冲突。
- 不支持超过 3 个工具的组合。
- 不修改书籍导入和工具匹配算法。

## 用户流程

1. 用户在“解决问题”中输入问题并查找工具。
2. 系统展示推荐结果，并默认勾选前 2 个工具。
3. 用户可调整选择，界面实时提示“已选择 N/3”。
4. 用户点击“组合使用已选工具”进入组合决策工作区。
5. 工作区按工具分组展示诊断问题、行动建议和不适用情况。
6. 用户填写综合判断，选择准备执行的行动。
7. 用户选择“仅保存应用记录”或“保存并生成待办”。
8. 应用记录关联所有工具；待办标题包含对应工具名称。

## 页面设计

### 推荐结果页

- 每个推荐工具卡增加复选框。
- 默认选中前 2 个非旧知识卡工具。
- 选择超过 3 个时阻止操作，并显示中文提示。
- 结果区底部提供固定操作行：已选择数量、清空选择、组合使用。
- 单个工具仍可打开查看，但详情页必须可返回带原问题的推荐结果。

### 组合决策工作区

- 顶部显示当前问题和“返回重新选择”。
- 每个工具使用独立分组，不把不同框架的内容混成一段。
- 诊断问题保持工具归属，便于识别不同分析视角。
- 行动建议使用复选框，选中值同时记录工具 ID 和工具名称。
- 不适用情况始终展示，作为决策边界，不参与自动合并。
- 底部只保留一份“综合判断”，防止产生多份互相割裂的结论。

## 路由与状态

- 推荐结果仍位于 `/knowledge`。
- 组合工作区使用 `/knowledge/solve?problem=...&toolIds=id1,id2`。
- 单工具详情返回链接使用 `/knowledge?problem=...`，知识首页读取参数后自动恢复问题并重新匹配。
- 页面刷新后，问题和所选工具仍可由 URL 恢复。

## 数据结构

现有 `LocalKnowledgeApplication.toolIds` 已支持多个工具，无需迁移。

为避免行动来源丢失，新增可选字段：

```ts
selectedActionSources?: Array<{
  toolId: string;
  toolName: string;
  action: string;
}>;
```

保留现有 `selectedActions: string[]`，兼容已有应用记录。新记录同时写入两个字段。

## 边界与错误处理

- URL 中不存在的工具 ID 自动忽略。
- 没有有效工具时返回推荐结果页，并保留问题。
- 保存前必须有问题；生成待办前至少选择一个行动。
- 相同行动文字来自不同工具时分别显示来源，但 `selectedActions` 中去重，来源字段保留全部归属。
- 旧知识卡不进入组合工作区，仍沿用原详情页。

## 测试

- 默认选择前 2 个工具，最多不超过 3 个。
- URL 能恢复问题和所选工具。
- 无效工具 ID 被忽略。
- 组合保存时记录多个 `toolIds` 和行动来源。
- 生成待办时标题包含正确的工具名称。
- 单工具详情返回后能恢复问题和推荐结果。
- 既有单工具应用记录继续正常显示。

## 验收标准

- 用户能从推荐结果返回并重新选择，不丢失原问题。
- 用户能组合使用 1 至 3 个决策工具。
- 保存后的应用记录只生成一条，并关联全部工具。
- 每项行动可以追溯到对应工具。
- 全部界面文案为中文，移动端和桌面端无内容重叠。

# 行动工作台首页设计

## 目标

将首页从静态数量统计页改为个人供应链行动入口。用户打开首页后，应能快速回答：

- 当前有哪些事情需要处理；
- 正在跟进哪些产品、供应商或货盘；
- 最近沉淀了哪些可回看的信息；
- 下一步可以直接做什么。

首页不承担完整资料库功能。供应商、货盘、产品知识和商业知识仍由各自的列表页负责浏览、搜索和详情查看。

## 用户界面

首页按以下顺序展示：

1. 顶部标题和“快速录入”主操作。
2. “待处理事项”：显示未完成的高优先级待办、已到期或即将到期的待办，以及需要确认的事项。
3. “当前置顶工作”：显示用户置顶的供应商、货盘、产品知识和商业知识卡；每项只显示标题和一行摘要。
4. “最近沉淀”：跨模块显示最近录入的少量记录，按时间倒序排列。
5. 次要快捷入口：待办、报价对比和各资料库，不再用数量卡片占据主要空间。

空状态要给出下一步行动，例如“还没有待办，先从快速录入开始”，而不是只显示 0。

## 数据规则

- 待办只显示 `status = open` 的记录；优先级按 high、medium、low 排序，再按创建时间倒序。
- 已完成待办不在首页显示，但保留在待办页。
- 置顶工作从现有 `pinned` 字段读取，按置顶状态和更新时间排序。
- 最近沉淀合并供应商、货盘、产品知识和商业知识卡，按 `createdAt` 倒序取少量记录。
- 记录摘要使用已有字段：供应商使用主营类别或地区，货盘使用报价/规格，产品知识使用材料或关键参数，知识卡使用 summary。
- 不新增独立的首页数据副本，避免首页和资料库数据不一致。

## 交互与边界

- 点击待办进入待办页或对应详情操作。
- 点击置顶工作进入对应详情页。
- 点击最近沉淀进入对应详情页。
- 首页只提供快速入口，不在首页编辑复杂字段。
- 移动端保持单列；桌面端使用清晰的两栏或分区布局，不使用卡片嵌套。

## 不做的内容

- 暂不加入销售漏斗、趋势图、库存统计等经营分析图表。
- 暂不加入复杂的“当前项目”实体；先使用置顶记录表达当前工作重点。
- 暂不复制或重构现有资料库数据模型。

## 验证标准

- 有待办时，首页首先显示可执行事项，而不是数量统计。
- 置顶的供应商、货盘、产品知识和知识卡能集中显示并可点击进入详情。
- 新录入记录会出现在最近沉淀中。
- 没有数据时，页面仍提供明确的下一步操作。
- 页面不出现重复数据、空字段占位或大段原始文本。
- 现有导航、详情页、置顶功能和本地数据不受影响。

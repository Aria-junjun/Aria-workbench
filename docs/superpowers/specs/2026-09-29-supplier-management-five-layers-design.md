# 供应商管理总览五层决策界面设计

## 目标

把供应链总监管理总览从当前纵向堆叠的经营数据，重组为“供给保障、交付履约、质量与综合成本、成本改善、责任闭环”五个可切换决策主题。重点是明确暴露风险与数据覆盖，不因字段缺失而删掉目标指标或生成推测结果。

## 页面结构

1. 页面标题和评估周期。周期按主题标注真实数据覆盖范围；入仓月度快照、采购履约事件、代发周期和聚水潭评分周期不强行伪装成同一口径。
2. 全局关注信号条：有证据的待跟进、逾期履约/未交事项、单一来源且未验证替代、未关闭质量异常、已核实增量费用、已实现降本。没有来源时显示“未采集”，不得写成零或“正常”。
3. 五个主题切换器。一次只展开一个主题，减少页面高度；主题状态数或数据覆盖提示留在切换器上。
4. 活跃主题内采用“关键判断指标 + 可排序业务表 + 原始依据/下一步入口”。不显示审批/驳回操作，总监只读；执行仍由业务负责人承担。

## 五个主题与数据边界

### 供给保障

按产品列实际供应商数、最大供应商占比、是否单一来源、已登记备选和验证状态。集中度只代表暴露，不直接判为供应商绩效差。关联现有入仓快照与产品供应关系；“已验证可替代”仅在有核验记录时成立。

### 交付履约

以采购订单行/到货事件为粒度，展示订单与批次、下单日、承诺发货/到货日、实际发货/到货日、未交/部分交数量、延期情况。只有承诺到货与实际到货都存在才计算到货准时率；只有实际日期时展示可计算的实际时长，不推导准时率。

### 质量与综合成本

按可追溯异常事件列批次、异常/拒收数量、责任与关闭状态、已核实额外费用及费用是否已计入结算。无成本金额字段时明确“未采集”，预计影响与已核实影响分开；不得重复计入结算。

### 成本改善

比较同产品/SKU/规格、单位和交易条件下的基准单价与实际可比单价。已实现降本仅对已发生且口径一致的数量计算；机会值另列。若当前数据没有可比基准或单位/条件信息，保留栏目并显示“未采集/不可比”。

### 责任闭环

汇集有原始业务依据的异常及重点事项，展示负责人、下一动作、期限、状态、处理结论/影响，并能打开来源记录。总监视图只读。

## 现有数据现实

- 月度入仓快照可支持实际入仓量、结算金额、部分库存/在途和来源；不等于订单履约/综合成本。
- 采购履约记录有下单日期、发货/收货事件、部分拒收和异常处理信息；承诺到货、数量汇总、已核实增量费用要按实际字段逐项判定，不存在的字段显示“未采集”。
- 代发继续使用代发周期数据和既有风险判断，不并入入仓口径。
- 聚水潭评分只呈现导入的原生结果；无评分结果时保留诚实空状态。

## 不在本轮范围

- 不接通未经确认的聚水潭 API，不编造接口字段、凭证或数据。
- 不建立全新财务分摊/增量成本录入系统。
- 不改变供应商档案、业务明细和导入批次删除的既有流程。
- 不添加总监审批/驳回。

## 验收标准

- 五个主题均可访问，默认只显示一个主题内容；全局信号有真实来源或明确显示未采集。
- 任意“准时率、增量费用、降本”计算都满足字段和口径前提；不满足时绝不补值。
- 交付、质量、成本记录能够返回业务来源；执行入口不要求总监直接维护业务事实。
- 代发与入仓仍分开判断，聚水潭原生分数不与工作台评分合并。
- 页面不再一次纵向展开五个大表，兼容窄屏并保留表格横向滚动。

# 供应商管理总览：总监决策与异常闭环设计

日期：2026-09-29  
状态：设计已确认，进入实施；目前没有聚水潭供应商绩效结果表，因此本阶段提供标准接入契约和决策视图，不承诺直连聚水潭 API。

## 1. 目标与边界

设计起点不是当前页面已经采集了什么，而是供应链总监需要做哪些判断，再倒推指标和数据源。管理总览不是业务明细的重复页，也不是把缺失字段补成 0。它要回答总监的四个问题：

1. 供应结构是否过度集中，关键产品有没有经过验证的替代来源？
2. 哪些履约/成本异常已经发生，影响金额和责任证据是什么？
3. 采购成本相对可比基准是在改善还是恶化，改善是否真实落地？
4. 现在需要谁采取什么动作，何时回报；哪些事项才需要总监介入？

范围仅限供应商管理：入仓采购和代发分业务展示；不接财务分摊，不把供货模式标签当实际业务事实，不改动原始导入记录。业务负责人负责补证、提出建议和执行；总监当前只读查看，不做批准/驳回，但数据结构保留后续审批扩展位。

## 2. 总监需要观察的结果（目标指标先行）

总览按“供给保障 → 交付履约 → 质量与综合成本 → 成本改善 → 责任闭环”组织。先定义判断，再根据实际导出/API/文件识别可获得字段；数据未接入只标“未采集”，不因此删掉目标指标。

### A. 供给保障：会不会断供、有没有真实替代

- 关键产品的实际供方数量、最大供方占比、单一来源产品数；同时区分“登记备选”和“完成验证的可替代供方”。
- 决策：是否需要开发/验证第二来源、是否调整主供份额。集中度是暴露，不直接等于供应商绩效差；阈值需要后续结合品类重要性和历史波动设定。

### B. 交付履约：承诺是否兑现，问题卡在哪个环节

- 按采购订单行/到货批次计算准时到货率、平均/中位交期、延期天数分布、未交/部分交数量、逾期未到订单金额或数量。
- 决策：催交、拆单/改期、启用备选、调整下次份额，或追查我方下单/物流环节。
- 时间链：下单日 → 承诺发货日/实际发货日 → 承诺到货日/实际到货日。准时到货必须比较承诺到货日与实际到货日；只有实际发货日时，只能计算发货等待/发运及时性，不能替代到货准时率。

### C. 质量与综合成本：异常实际造成多大损失

- 质量异常数量/批次、返工/补发/退换货数量、问题关闭时长；按有凭证且核实的直接增量费用汇总。
- 增量费用按事件关联并去重：返工、补发、加急物流、额外检验等；预计影响与已核实影响分列，并标记是否已计入采购结算，避免双计。
- 决策：整改期限、复检/暂停该批次、索赔或替代供货。没有质检/售后证据时，不推导质量合格率。

### D. 成本改善：低价是否可比，降本是否真实实现

- 同产品/SKU/规格、单位、税费与运费口径、付款/交付条件下，对比有效基准价与实际采购价。
- 已实现降本 =（有效基准单价 - 实际可比单价）× 实际可比采购数量；只对已发生且口径一致的数量计入。未来谈判空间作为“机会值”单列，不混成已实现结果。
- 决策：议价、合并份额、调整采购条件，或维持现有供应。全供应商混合单价不可横向比较。

### E. 责任闭环：异常有没有被解决

- 重点事件必须有原始记录、责任人、下一动作、期限、处理状态、复盘结论；呈现未核实、处理中、逾期、已关闭和确认影响。
- 决策：业务负责人执行并反馈；总监只读查看，必要时推动资源或供应策略变化，暂不审批/驳回。

## 3. 数据来源盘点：从目标往回映射

聚水潭供应商绩效按用户提供的信息，是优先核验的数据来源；但当前不能据此假设本工作台已接通接口，也不能先认定导出的列名、粒度和口径。第一步应拿实际导出表/接口字段做映射，至少核实订单行唯一键、供应商ID、产品/SKU、下单时间、承诺/实际发货时间、承诺/实际到货时间、订购/实收数量、取消/退货数量、异常原因及更新规则。

| 目标结果 | 优先来源 | 可以转换/聚合的方式 | 不能用什么替代 |
|---|---|---|---|
| 供应商准时到货率 | 聚水潭采购订单行或供应商绩效明细：承诺到货日、实际到货日、订单/行状态 | 准时且有效到货的订单行数 ÷ 本期应到订单行数；另列未到/取消处理规则 | 月度结算额、入仓月汇总；预计发货日对比实际到仓日 |
| 实际交期、延期天数 | 同一订单行的下单、承诺/实际发货、承诺/实际到货节点 | 实际到货日-下单日；延期=实际到货日-承诺到货日；分开看中位数、P90和逾期积压 | 只凭月度入仓周期推断单笔交期 |
| 数量履约率/欠交 | 订单订购数量、实收数量、取消/变更状态 | 有效订单行实收量÷有效订购量；部分交货按订单行累计并防重复 | 单看入仓数量总和，不知道应交数量 |
| 质量异常率/质量损失 | 聚水潭售后/质检/退换补记录或单独事件凭据 | 问题批次/数量对有效收货批次/数量；按原因分组，分母需定清 | 退款率直接等同质量问题；没有原因码的退货一律归因供应商 |
| 采购价偏差、实现降本 | 货盘报价/合同基准 + 同SKU/规格采购实绩 | 对齐单位、含税/运费、有效期后按真实采购量加权 | 跨产品平均单价、月结总额变化直接称降本 |
| 质量/延期增量成本 | 异常事件凭证 + 采购/履约/售后来源 | 事件级核实金额求和，标识已入结算与否 | 仅用异常次数推算损失金额 |
| 供应集中/替代能力 | 已归属采购/入仓事实 + 供货关系及备选验证记录 | 同产品口径算份额；备选验证完成后才计为可替代 | 把档案里登记了备选供应商当作已具备替代能力 |

当前工作台已知的月度入仓快照主要可支撑月份、供应商、产品/SKU、实收/入仓数量、结算单价/金额与来源批次。它可补充总览中的采购结果和结构，但不能替代订单行履约事实。原始记录保留，不因接入更高颗粒度绩效而重复导入或覆盖。

## 4. 当前数据与目标数据的状态分层

- **可直接呈现**：现有来源字段可以支撑，展示覆盖率与口径。
- **可转换待核验**：理论上由源字段计算，但必须先拿聚水潭实际导出/接口样本，验证字段、唯一键、取消/部分到货规则和重复更新行为。
- **未采集**：源系统未提供或当前尚未接入；保留目标指标位置，清楚显示“未采集”，不记作 0。
- **不可比较**：缺少相同SKU/单位/税运/有效期等可比条件，不排名、不计分。

任何衍生指标必须保存数据期间、来源记录范围、公式版本和缺失覆盖情况，支持从指标追到订单/批次；若不能追溯，不进入总监决策排名。

## 5. 当前数据基线与不可推断项

### 当前入仓快照可证明

- 月份、供应商、经营产品/SKU；
- 实际入仓数量；
- 结算单价和/或结算金额；
- 来源文件、工作表、导入批次。

### 当前不能可靠计算

- 是否按承诺日期到货、延期天数、供应商准时交付率：现有快照没有采购单/批次粒度的下单日期、承诺到货日、实际到货日。预计发货日不能与实际到仓日直接比较来判断准时到货；
- 延期是否造成代发补货/加急等额外成本：没有关联的事件记录和已确认金额；
- 年度已实现降本：没有同一产品/规格、同口径的锁定基准价、实际可比采购数量及有效期间；
- 跨产品供应商综合单价：不同产品/规格混算无可比性；
- 库存风险：现有库存/在途字段并非稳定、完整的可用数据源。

以上一律显示“未采集/不可判断”，不显示 0、不做推算、不据此自动判风险。

## 6. 总览版式与职责

页面保留三个决策层，使用统一表格、轻量口径问号和右侧动作入口，不展开原始明细：

### A. 供应组合（结构风险）

| 展示项 | 当前数据口径 | 触发后动作 |
|---|---|---|
| 供应商集中度 | 按所选期间、仅对已归属且有结算金额的入仓记录，列最大供应商金额占比；同时展示金额覆盖率 | 高集中只提示“需评估备选”，不能直接等同高风险 |
| 单一来源产品 | 产品在所选期间只有一家实际供方；和已登记的主供/备选关系并列，但必须区分“实际供方”与“仅登记备选” | 产品负责人补充备选验证计划；记录验证结果后才能把备选称为可替代 |
| 未归属/缺失记录 | 未关联供应商金额、缺结算金额行数、未映射产品行数（可计算才显示） | 跳转对应导入批次/记录修复，不在总览直接改原始事实 |

不把“供应商数量”或“金额总额”单独包装成绩效。集中度阈值首期不硬编码为红线，先显示数值并由管理者确认阈值，避免凭空设标准。

### B. 绩效与成本偏差（经营结果）

第一阶段只展示有证据的结果：所选期间结算金额、入仓数量、覆盖/缺失比例，以及同产品同规格下可比的结算单价变化（仅当基准价与采购口径一致时）。当前供应商级“参考结算单价”从总监主表移除；必要时下钻到产品/SKU可比分析。

后续成本指标严格分层：

- 采购价偏差 =（本期同产品同规格结算单价 - 锁定基准单价）× 可比入仓数量；
- 已确认异常增项 = 事件中状态为“已核实”的直接费用之和；
- 调整后采购成本 = 同口径采购结算额 + 已确认且未重复计入结算额的异常增项；
- 年度已实现降本 =（基准单价 - 实际可比单价）× 实际可比数量；机会值单列，不与已实现降本合并。

基准单价必须绑定产品/SKU、规格、计价单位、税/运费口径、有效期和来源报价/协议。未满足这些条件的行只标“口径待核”，不排名、不计分。

### C. 风险责任与决策动作

总览只呈现已登记的重点、待决定、逾期事项，以及经规则识别且有原始记录依据的异常。每一项必须能看到：业务类型、供应商/产品、异常数值与口径、证据链接、负责人、截止日、下一步动作、处理状态、实际影响金额（未知则写未核实）。

风险不是红字标签；每条必须回答“什么异常、偏离多少、证据在哪、谁处理、下一步是什么”。没有证据的推测列为“待核实线索”，不可计入已发生损失或供应商绩效。

## 7. 异常事件采集字段：只在发生时填写，不做全量重复录入

新增/复用一个跨入仓与代发的“供应异常事件”记录，作为异常事实及后续责任跟踪，不代替采购单、入仓快照、代发周期表现或财务账。

最小字段：

- 事件编号、业务类型（入仓/代发）、供应商档案 ID、产品/SKU；
- 关联采购单/履约批次/导入批次 ID（至少一个可定位来源）；
- 事件类型（晚到、少到/错发、质量问题、返工/补发、加急运输、其他）；
- 发生日期、承诺到货日（如适用）、实际到货日（如适用）；
- 影响描述、数量、证据附件/来源记录；
- 预计影响金额及其依据；核实后金额、确认状态、是否已计入结算金额（防止双计）；
- 业务负责人、下一步动作、截止日、状态（待核实/处理中/待复盘/已关闭）；
- 复盘结论：供应商原因/我方原因/物流或外部原因/原因未明，责任判断需有证据。

只有“核实后金额”进入已确认异常增项；预计金额单列。延期天数只在承诺到货日和实际到货日均存在时计算。实际发货日可作为后续区分生产等待与运输时长的补充字段，但不是首期计算准时到货的必填条件。

## 8. 当前工作台字段映射

| 指标/事实 | 数据源 | 当前能否呈现 | 不足与处理 |
|---|---|---:|---|
| 月度结算额、入仓量、产品/SKU供应分布 | 月度入仓快照与导入批次 | 是 | 标明是已导入数据，不等于已付款/全量采购 |
| 金额覆盖率、未关联供应商金额、缺金额记录 | 同上 | 是 | 分母只用可识别记录；明确覆盖口径 |
| 产品供应集中/单一来源 | 入仓快照 + 有效供应商关系 | 部分 | 登记备选不能证明可替代，需单独验证状态 |
| 可比采购价偏差 | 货盘报价/协议 + 同SKU规格入仓快照 | 需核查口径 | 锁定基准价、单位、税运口径、有效期；未齐不计算 |

| 延期/质量导致的增量成本 | 供应异常事件 + 费用凭据 | 当前缺 | 事件录入预计/核实金额，标记是否已计入结算 |

| 责任闭环率/逾期事项 | 异常事件/现有风险事项的负责人、期限、状态 | 部分可用 | 仅统计有负责人和期限的记录；未登记不等于无风险 |

## 9. 操作路径与闭环

1. 业务负责人导入采购/入仓数据；系统按已有供应商、产品映射归属，展示未匹配和数据覆盖；
2. 业务负责人只对异常或需要管理决策的事项建事件，关联原始业务记录，不重复抄录订单金额/数量；
3. 负责人补证据、预计影响、动作和截止日；核实金额需注明凭据并勾选是否已在结算中；
4. 总览按“风险优先级、影响金额、逾期程度”排序。总监查看证据并识别需要资源/供应策略变化的事项；当前不提供批准/驳回按钮；
5. 业务负责人执行并复盘，关单时记录结果；总览显示待处理、逾期、已关闭及真实影响，不以填写完成作为绩效完成。

建议决策排序：供应中断/关键产品单一来源与未验证备选 → 已发生且金额较大的质量/延期事件 → 已确认单位成本恶化或可实现降本 → 数据缺口。单纯数据缺失进入数据质量队列，不冒充业务风险。

## 10. 分阶段方案与取舍

### 推荐：先做可信的最小闭环

1. 调整总览：去掉总监层无决策价值的混合“参考结算单价、库存/在途”；保留可证实的金额/数量、金额覆盖、供应集中和异常责任表；供应组合与成本偏差、风险责任三层明确分区。
2. 补充采购履约批次最小日期：下单日、承诺到货日、实际到货日；如果当前业务确实只有预计发货日，则先记录但不计算到货准时率。
3. 上线异常事件的轻量表单和证据关联；预计损失和已核实金额分开，防双计。
4. 先积累至少一个完整采购周期后，再启用交付趋势与可比成本趋势；年度降本需跨周期基准后再展示。

优点：先形成真实可操作的管理闭环，不要求把所有采购数据重新录一遍。代价：短期无法给出供应商交付排名或年度降本结论。

### 更快但更弱：只调整现有总览

立即改版、隐藏弱字段、把“处理入口”指到记录核对。成本最低，但没有订单/事件粒度证据，风险和交付问题仍依靠线下补充，无法闭环，不建议当作最终方案。

### 更完整但成本更高：逐采购批次履约与异常成本管理

为每张采购单/每个产品行记录完整承诺与实际节点，事件金额、责任和复盘全流程。长期最好，但需要确认采购履约模块已经有可复用单据号与人员日常录入能力；否则会造成双重录入和低质量数据，不应一次铺开。

## 11. 验收标准

- 页面不会把未知值显示为 0；所有金额/比率都有明确分母和口径说明。
- 供应商级混合单价不作为横向绩效排名依据；成本比较必须同 SKU/规格/计价与税运口径。
- 每个管理风险均可跳转到证据和原业务记录，并能看到负责人、期限、下一步和状态。
- 预计影响与核实金额分开；已计入结算的费用不重复计入调整后成本。
- 交付及时率只在承诺到货日、实际到货日有效时计算；年度降本只在有有效基准和真实可比数量时计算。
- 供应商结构风险与已发生异常分开：集中度是暴露，不自动等同事故/供应商绩效差。
- 总监只读查看；业务负责人承担提报、补证、执行与复盘。

## 12. 下一步核验项

后续接入真实绩效前需完成以下核验，避免系统替管理层臆设或按错数据口径：

1. “关键产品/关键供应商集中度”首期只展示分布、暂不触发红黄灯，推荐作为默认方案；待按品类重要性和历史表现设阈值。
2. 采购计划中的 `expectedDate` 当前虽命名为期望到货日期，但用户实际提到的现有业务日期可能是“预计发货日”。要以真实源表字段和实际填报习惯核验，不能复用歧义字段。
3. 获取一份聚水潭供应商绩效导出样表（脱敏即可）或字段/API清单后，再完成目标指标到实际字段的逐列映射，并确认订单行唯一键、状态及部分到货/取消规则。未拿到样表前，聚水潭具体字段映射、API可行性和覆盖范围均标记为待验证。

## 13. 本阶段实施范围（已确认）

- 新增独立的供应商原生绩效导入契约/批次数据结构，包含供应商、业务类型、评分期间、方案名称及版本、原生总分/等级、各指标原始值、来源和批次标识；不把导入结果写入会覆盖同周期手工评价的保存路径。
- 接入层先支持契约化数据导入与校验；不构建未经授权/验证的聚水潭直连客户端，不生成虚构绩效结果。
- 管理总览明确区分聚水潭原生评价、工作台业务判断和数据未采集状态；优先呈现真实业务记录可支撑的供给结构、代发表现、入仓结果和风险责任动作。
- 每个异常/动作须回到对应来源记录或供应商档案；缺少证据、负责人或下一步的事项不得伪装成已闭环决策。
- 保留现有供货业务数据与记录；仅新增可选字段/数组并兼容旧数据，不批量重写或删除既有供应商评价。
- 聚水潭方案权重及评分等级阈值按方案版本保存；不得用工作台自有权重重算或覆盖聚水潭原生分数。

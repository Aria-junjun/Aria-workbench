# 知识导入完整性审计设计

## 目标

验证书籍知识在“ChatGPT 书籍包 → 工作台解析 → 决策工具入库”过程中是否发生信息丢失，并在不覆盖人工修改、不破坏工具 ID 和历史应用记录的前提下恢复可确认的解析遗漏。

本功能只解决解析完整性，不声称验证一本书的知识是否完整。若原始书籍包本身已经省略内容，系统必须明确提示需要回到原始笔记、截图或完整整理结果重新生成，不能自行补写。

## 审计入口

书籍详情页增加“检查导入完整性”入口。只有书籍保存了原始书籍包 `rawText` 时才可执行。

点击后在当前页面展示审计结果，不立即修改数据：

- 当前入库的决策工具数量。
- 从原始书籍包重新解析出的工具数量。
- 每个同名工具当前与重新解析结果的条目数量对比。
- 可恢复的触发信号、诊断问题、行动建议、不适用情况和标签。
- 原始包中新出现、当前尚未入库的工具。
- 无法从原始包恢复时，明确标记“源书籍包本身信息不足”。

## 解析规则

解析器同时支持以下字段格式：

```text
行动建议：检查客户细分；检查价值主张
```

以及：

```text
行动建议：
1. 检查客户细分
2. 检查价值主张
- 检查渠道
```

字段内容读取到下一个已知字段标签或下一个 `【决策工具】` 为止。解析时移除开头的项目符号和编号，但保留正文；空行不生成条目。

## 安全修复规则

- 同名工具保留现有 `id`、`bookId`、创建时间和历史关联。
- 对列表字段采用去重合并，只补充原始包中存在但当前缺失的条目。
- 对名称、问题描述和来源章节等单值字段，只在当前为空时补充，不覆盖现有内容。
- 原始包中新出现的工具可新增入库。
- 当前已有但原始包未解析出的工具不删除。
- 应用修复前必须由用户点击确认。

## 审计结论

审计结果分为三种：

1. **发现可恢复遗漏**：解析器从原始包找到了当前未入库的内容。
2. **未发现解析差异**：当前入库结果与原始包一致。
3. **源材料不足**：关键模块仍只有零到一条，重新解析也无法恢复；系统提示重新整理原始资料，而不是自动扩写。

“源材料不足”的判断用于提醒，不作为知识质量的最终评价。最低检查信号为：诊断问题少于 2 条，或行动建议少于 2 条。

## 验收标准

1. 多行编号和项目符号列表能完整解析。
2. 单行分号格式保持兼容。
3. 审计页能显示当前值、重新解析值和可恢复差异。
4. 未确认前不修改本地数据。
5. 确认修复后只补充内容，不覆盖或删除现有内容。
6. 现有工具 ID 与历史应用关联保持不变。
7. 原始书籍包本身不足时给出明确提示。
8. 全部自动化测试和生产构建通过。

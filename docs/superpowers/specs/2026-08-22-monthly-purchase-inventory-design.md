# 月度采购库存数据入口设计

## 目标

为已入仓产品建立最小可用的月度采购与库存数据入口，把聚水潭销售数据、内部 SKU 编码和月度采购库存快照连接起来，为后续产品供应策略与供应链驾驶舱提供可追溯的数据基础。

## 范围

本阶段只处理已入仓产品，不把一件代发产品纳入库存周转或供应绩效判断。

本阶段不做：

- 日级库存监控
- 拆箱/释放库存的精确事件管理
- 财务利润核算
- 聚水潭 API 对接
- 供应商自动评分重构
- 采购订单执行管理

## 页面入口

在“入仓产品主表”现有“导入聚水潭月度表”旁边增加“导入采购库存月报”。入口使用相同的统计月份选择器，导入后先预览，确认后写入对应月份；历史月份不覆盖。

## 导入字段

必填字段：

- 商品编码：必须匹配已确认的内部 SKU 主表编码
- 采购数量：本月实际采购数量
- 实际到仓数量：本月实际到仓数量
- 月末实际库存：月末仓库实际持有数量
- 月末可用库存：月末当前可销售/可分配数量

可选字段：

- 采购在途数量
- 供应商

系统同时显示并校验一个文件级“采购总量”结果：按 SKU 汇总的采购数量必须可追溯；不额外要求用户填写一个不可校验的总量字段。

## 数据处理规则

1. 只写入能匹配内部 SKU 编码的行。
2. 未匹配编码进入预览错误区，不写入主数据。
3. 同一 SKU、同一月份重复导入时，必须在确认前提示“将替换该 SKU 该月份的采购库存快照”，不得静默覆盖。
4. 空白数值保持为空，不自动填 0；明确的 0 才保存为 0。
5. 采购数量、到仓数量、库存数量不得为负数。
6. 供应商为空不影响库存数据保存；供应商有值时按现有供应商名称或 ID 关联，无法关联时保留原始文本并标记为待确认。
7. 该快照与既有 `skuOperatingSnapshots` 分开保存，不能覆盖销售、退货或 ERP 成本字段。

## 最小产出指标

产品主表按产品族汇总展示：

- 本月采购数量
- 本月实际到仓数量
- 月末实际库存
- 月末可用库存
- 库存差额：实际库存 - 可用库存，仅称为差额，不推断为未拆箱库存
- 采购/实发比例：本月实际到仓数量 ÷ 本月实发数量；实发为 0 时显示“暂无销售样本”
- 库存变化：本月末实际库存 - 上月末实际库存；没有上月快照时显示“缺少上月基准”

本阶段不计算精确库存周转天数，直到至少有月末实际库存、月末可用库存和可比销售数据。后续可用近 15 天或月度实发计算估算覆盖天数，并明确标注为估算。

## 预览与反馈

导入预览必须显示：

- 文件名、工作表名、写入月份
- 总行数
- 可导入行数
- 未匹配行数
- 字段错误行数
- 前若干行的商品编码、采购数量、到仓数量、实际库存、可用库存
- 确认导入和取消按钮

保存成功后显示写入行数、未写入行数和月份，不改变当前产品主表的销售快照。

## 后续承接

第二阶段的“产品供应策略”读取本阶段的月度库存快照和现有货盘/供应商关联，按产品族显示主供、备供、覆盖情况和供应异常。第三阶段的“供应链驾驶舱”只读取已经存在的指标和异常，不新增重复录入。供应商绩效与协同记录继续使用事件发生时记录、月度复盘汇总的低频方式。

## 关键风险与处理

- “实际库存 - 可用库存”不一定等于未拆箱库存，因此界面只显示库存差额。
- 采购数量不等于实际到仓数量，两个字段必须分开保存。
- 单月数据只能形成当前快照，不能判断趋势；趋势判断需要至少两个月快照。
- 同一产品族不同 SKU 的销量可能差异很大，产品族汇总只用于方向判断，明细仍保留 SKU 层。

# 待办截止日期与工作台内提醒设计

## 目标

将待办的自由文本截止时间升级为可选择的标准日期，并在工作台内根据截止日期显示逾期与即将到期状态，同时保留旧待办数据。

## 范围

- 新建待办支持日期选择。
- 编辑待办支持修改或清除截止日期。
- 旧字段 `dueText` 继续保留，用于兼容历史数据和自然语言日期。
- 新增可选字段 `dueDate`，格式固定为 `YYYY-MM-DD`。
- 打开、刷新或切回工作台时根据当前日期重新计算提醒状态。
- 不实现浏览器系统通知、邮件、微信或后台定时任务。

## 数据与兼容

`LocalTask` 新增 `dueDate?: string`。新建和编辑时，日期输入值写入 `dueDate`；如果旧数据只有 `dueText`，继续原样显示，不强行猜测日期。清除日期时同时清除 `dueDate`，但不覆盖历史 `dueText`，以免丢失原始记录。

## 提醒规则

- `overdue`：未完成且 `dueDate` 早于今天。
- `due_today`：未完成且 `dueDate` 等于今天。
- `due_soon`：未完成且距今天 1–3 天。
- `normal`：未完成且距今天超过 3 天，或没有标准日期。
- 已完成待办不进入逾期和即将到期统计。

顶部只显示未完成的“已逾期”和“即将到期”数量；点击后使用现有筛选机制查看对应待办。卡片显示中文状态，不改变现有优先级判断。

## 失败与边界

- 日期为空时不触发到期提醒。
- 非标准旧 `dueText` 不参与日期计算。
- 使用本地日期而不是 UTC 日期，避免东八区跨日误判。
- 日期提醒是展示层计算，不写入快照，避免每天产生无意义的数据变更。

## 验收标准

1. 新建待办可以点选日期并保存，刷新后仍显示该日期。
2. 编辑已有待办可以修改或清除日期。
3. 逾期、今天到期、1–3 天内到期分别显示正确状态。
4. 已完成待办不计入逾期或即将到期数量。
5. 没有 `dueDate` 的历史待办仍可正常显示和编辑。
6. 现有待办创建、完成、删除、复盘和云端同步测试不回归。

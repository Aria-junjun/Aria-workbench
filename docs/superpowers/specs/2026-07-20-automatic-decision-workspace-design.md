# 自动决策整理入口设计

## 目标

用户只需用文字、口述转文字或截图描述实际问题、已知事实和初步判断。工作台默认只保存原始记录，不自动解析。只有用户明确点击“需要分析”后，才按需调用一次 AI，判断是否需要决策模型；需要时把原话归入合适模块并提出少量关键追问，不需要时直接整理为普通判断记录。

核心原则：省钱、省力地沉淀并应用知识，不为了展示模型而增加填写负担。

## 用户流程

1. 用户在“解决问题”入口描述问题、事实和初步判断。
2. 用户可以直接保存为普通应用记录，此路径不调用 AI、不选择模型。
3. 只有用户明确点击“需要分析”后，本地才清理重复内容并控制输入长度，然后调用一次 AI。
4. AI 先判断是否需要模型。简单跟进、事实记录或已有明确结论的事项不套用模型。
5. 需要模型时，AI推荐一个备选模型；只有确有互补价值时最多推荐两个，由用户确认是否使用。
6. 用户确认模型后，系统才把原话归入模型模块；商业模式画布不得默认启用。
7. 缺少影响决策的关键事实时，最多提出3个追问；不重要的空白不追问。
8. 用户检查并修改整理草稿，确认后保存。
9. 后续新增结果或事实时，在原记录上生成新版本；默认展示最新版，可查看历史版本。

## 展示方式

- 不建立大量独立表格入口，也不要求每条记录进入模型。
- 页面展示“问题、采用模型、结构化判断、关键缺口、下一步行动”。
- 未使用模型的记录只展示原话、初步判断和行动。
- 商业模式画布等模型以模块化区域呈现，但必须由用户确认启用；启用后由系统自动填入，不要求用户逐格填写。
- 空模块显示浅灰色参考示例，说明应填写的内容；示例不得作为用户结论保存。
- 应用记录列表只显示问题摘要、核心判断、下一步行动和更新时间，完整内容进入详情页查看。

## 第一阶段备选模型

第一阶段将商业模式画布作为备选工具之一，而不是默认处理方式。现有决策工具仍可参与推荐，但不预装大量新工作表。只有问题确实涉及完整商业逻辑，例如客户、价值、渠道、收入、资源和成本之间的关系时，才建议商业模式画布。

普通供应商跟进、待办记录、单次报价判断、信息归档和已有明确结论的事项，不推荐商业模式画布。

商业模式画布包括：客户细分、价值主张、渠道通路、客户关系、收入来源、核心资源、关键业务、重要合作、成本结构。

## 通用扩展结构

决策模型由配置描述，而不是写死页面。每个模型包含：

- 模型名称与适用场景
- 模块名称与浅灰参考示例
- 关键追问规则
- 输出约束
- 可选行动建议

以后可按需增加产品定位、单位经济、竞争战略、谈判准备、供应商风险和假设验证等模型，无需迁移已有记录。

## 数据保存

每次应用保存：

- 原始问题与原话
- 模型ID和版本
- 自动归位后的模块内容
- 用户补充与修改
- 未确认的关键问题
- 最终判断和下一步行动
- 创建时间、更新时间和历史版本

原始输入必须保留，确保以后模型升级时可以重新整理；旧结果不得被覆盖丢失。

## AI成本控制

- 直接保存普通记录时不调用 AI。
- 仅在用户点击“需要分析”时调用。
- 一次输入只调用一次；追问回答优先本地合并，用户再次确认整理时才调用。
- 固定短结构输出，禁止长篇商业报告。
- 保存整理结果，重复打开不再次调用。
- 模型可以为零个；需要时默认推荐一个，最多两个，并由用户确认。
- 月度 API 限额继续作为总成本上限。

## 失败处理

- API不可用时保留原始输入，允许稍后重试，不生成虚假结构。
- 模型判断不确定时显示“建议模型”，由用户确认，不强行归类。
- AI未识别到的信息保持空白并显示参考提示，不得编造。
- 保存前所有模块均可编辑，也允许删除不适用模块。

## 验收标准

- 用户可以不经过分析直接保存普通应用记录，且不产生 API 调用。
- 系统不会为每条输入默认套用商业模式画布。
- 用户确认使用商业模式画布后，无需手工逐格填写。
- 一段包含事实和初步判断的描述，在用户请求分析并确认模型后可以自动归入相应模块。
- 追问不超过3个，并且只针对影响决策的缺口。
- 保存后可在应用记录中查看最新版和历史版本。
- 重复打开记录不产生 API 调用。
- 后续新增模型不要求修改已有应用记录的数据结构。

# 供应商板块职责与数据联动设计（2026-09-28）

## 目标与边界

同一事实仅采集一次。业务记录保存可核查事实，供应商档案维护身份和长期合作关系，管理总览形成跨记录判断和待办，货盘报价保存报价单及 SKU 价格。入仓与代发分别统计、分别评价；一家供应商可以同时经营两类业务。保留现有历史数据，不自动合并同名档案、不把缺失指标当作零。

## 页面与字段

| 页面 | 复用现有字段 | 新增或调整 | 移出该页 |
| --- | --- | --- | --- |
| 供应商业务记录 | 入仓月度快照、采购履约记录、代发周期记录、来源文件及批次 | 入仓/代发分视图；来源、期间、供应商、商品范围、数量金额、异常、归属状态、证据及纠错动作；供应商 ID 或待归属状态 | 按供应商重复汇总的绩效总览表 |
| 供应商档案 | 公司名称/简称、平台链接、业务联系人、业务范围、合作约定、商品及报价关联 | 入仓/代发各自联系人；有效约定与报价单摘要；按业务跳转到已筛选记录；停用不删除历史 | 可编辑的订单/周期绩效明细、单一“供应商单价” |
| 货盘报价 | 报价单、供应商 ID、多个 SKU 的规格、价格、MOQ、价格历史 | 报价版本、有效期、状态；采购引用报价单 ID + 报价 SKU ID，并保存当时价格快照 | 将多个 SKU 价格拼入一个档案字段 |
| 管理总览 | 入仓结算额与结构、代发周期聚合、生命周期待办 | 两个同构监控区：期间、4 个指标、数据覆盖、重点风险表、建议人/审批状态、证据与处理入口 | 原始导入表和重复绩效明细 |

## 单向数据流与归属

1. 导入或登记时保留原始记录、来源文件/批次、业务类型、时间范围、商品及供应商原名；只在唯一可靠匹配时写入供应商 ID，否则进入待归属队列。供应商档案允许先于业务记录建立。
2. 入仓采购和到货事实来自采购履约记录与月度入仓快照；代发事实来自周期履约记录。两类事实按供应商 ID、业务类型及期间独立汇总。`businessModel` 只作档案描述，不能作为实际业务归属的唯一依据。
3. 档案页读取关联摘要，不复制源记录。点击入仓/代发摘要跳到业务记录页并携带供应商、业务类型和期间筛选。
4. 总览显示计算结果及覆盖口径。风险、趋势与金额均可回溯到参与计算的原始记录；样本不足、缺失数据及未归属记录单独列示，不参与正式风险排名。
5. 报价单属于供应商，单价属于报价单下的 SKU 版本。采购任务/采购单引用具体报价版本和 SKU，另存成交价格快照，以免报价变更改写历史。

## 管理动作与留痕

业务负责人核对原始证据并提交建议（供应商、业务模式、期间、风险规则/人工原因、关联源记录 ID、建议动作、负责人、期限）。常规事项由业务负责人处理和复核；高风险事项在总监视图中重点呈现。当前总监只查看，不提供批准、驳回或退回操作。数据结构预留审批状态、审批人、审批时间和意见字段，均保持空值；未来启用审批时另行定义权限和状态迁移。每次执行状态变化留操作人、时间、意见及旧值，处理完成需填写结果和复核依据。高风险阈值先配置且可人工升级，不根据当前样本硬编码。

## 入仓与代发总览口径

两块使用相同视觉结构：期间选择 → 指标卡 → 数据覆盖/风险分布 → 可排序重点表 → 来源与处理入口。入仓指标候选为已知结算金额、实际入仓量、质量异常率、交期达成和综合成本；代发指标候选为周期订单量、GMV、48H 揽收、退款/售后与响应。某指标没有可靠原始字段时显示“未采集”，不得用零代替；已知入仓结算金额不得标成付款额或全部采购额。

## 实施顺序与验收

1. 建立统一关联/待归属视图，保持历史记录与原始文件不变；验证同名歧义不会误合并。
2. 业务记录页保留原始明细与纠错入口，移除重复供应商汇总；档案摘要能带筛选跳转并返回。
3. 两类总览采用同构布局但不同指标，金额、风险、样本与覆盖可追溯；缺失值不误判正常。
4. 报价单/SKU 关联采购价格快照；多 SKU 报价不再用一个档案单价代表。
5. 建立建议→总监只读关注高风险→负责人执行→复核的版本化留痕；预留审批字段但当前不开放审批操作。

本设计不新增财务结算模块，不自动从平台拉取订单，也不自动合并或删除历史供应商与记录。

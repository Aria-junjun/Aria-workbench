# 数据基础稳定化一期设计

## 目标

让一次快速录入形成可追溯、可修正的数据链：供应商 -> 沟通记录 -> 货盘/产品知识/待办，并避免同一供应商和同一待办反复入库。

## 数据模型

- 新增 `LocalCommunication`，保存沟通摘要、承诺、疑点、风险、下一步动作。
- `LocalOffer` 增加 `supplierId` 与 `communicationId`。
- `LocalProductKnowledge`、`LocalTask` 增加可选的 `supplierId`、`supplierName` 与 `communicationId`。
- 保留 `supplierName` 作为展示字段和旧数据兼容字段，但内部关联优先使用 ID。

## 入库规则

- 供应商按标准化名称匹配；命中时更新非空字段并保留原 ID、置顶状态和创建时间。
- 每次确认生成一条沟通记录，作为本次输入的原始业务上下文。
- 本次生成的货盘、产品知识和待办关联该供应商及沟通记录。
- 相同供应商下，标题相同且未完成的待办不重复新增。
- 货盘不按名称强制去重，因为同一货盘可能存在不同时间报价。

## 兼容策略

- 读取旧数据时自动补空的 `communications`。
- 对仅有 `supplierName` 的旧货盘，按供应商名称推断 `supplierId`。
- 旧数据不做破坏性重写；后续保存时自然升级。

## 确认页

- 展示全部货盘、产品知识、待办和知识卡，不再只展示第一条。
- 核心字段可以直接修改。
- 误识别的条目可以从本次草稿移除，不进入数据库。
- 确认入库仍保留本地模式现有流程。

## 详情页

- 供应商详情使用 `supplierId` 查找货盘，名称只作为旧数据回退。
- 增加该供应商的沟通时间线，展示每次沟通的承诺、风险和下一步。

## 本期不做

- Supabase/云端模型迁移。
- 手机端专项适配。
- SKU 明细和标准化计量模型重构。
- 图片持久化。
